Build a production-ready, mobile-first web app for calculating reconstituted peptide doses, scheduling injection cycles, and recording journal entries.

This must be a functional MVP, not a static mockup. All calculations, forms, navigation, editing, calendar population, and data persistence must work.

WORKING APP NAME
Use “Peptide Tracker” as a temporary name. Keep the name and logo easy to replace later.

PRODUCT GOAL
The app should let a user:

1. Calculate how much liquid to draw into a syringe based on vial strength, bacteriostatic water, and desired dose.
2. Turn that calculation into a scheduled cycle.
3. View scheduled injections in weekly and monthly calendars.
4. Track the current week of each cycle.
5. Edit doses, schedules, and cycle details without deleting historical records.
6. Record dose changes, observations, and general notes in a journal.

The app must not recommend doses or provide medical treatment advice. It only performs arithmetic and tracks information entered by the user.

PLATFORM AND TECH STACK
Build this as an installable, responsive Progressive Web App that works well on mobile and desktop.

Preferred stack:
- React with TypeScript
- Next.js or another modern React framework
- Tailwind CSS
- shadcn/ui or similarly clean component library
- PostgreSQL database
- Supabase for authentication, database, and row-level security
- Use the user’s local timezone for calendar events

Use current stable package versions.

NAVIGATION
Use a simple mobile bottom navigation bar with three primary pages:

1. Calculator
2. Calendar
3. Journal

Place Settings and Account access in a small icon in the top-right corner.

The Calculator should be the default landing page.

Clearly indicate that the calculations assume a U-100 syringe where:
- 100 syringe units = 1 mL
- 1 syringe unit = 0.01 mL

CALCULATION RULES

Normalize compatible mass units before calculating:
- 1 mg = 1,000 mcg

For mg or mcg inputs:

concentration = total vial amount / BAC water in mL

volume to draw in mL = desired dose / concentration

U-100 syringe units = volume to draw in mL × 100

Theoretical number of doses per vial = total vial amount / desired dose

For IU inputs:
- Vial strength and desired dose must both use IU
- Calculate IU per mL
- Do not attempt to convert IU to mg or mcg

Block incompatible conversions such as:
- Vial entered in mg and desired dose entered in IU
- Vial entered in IU and desired dose entered in mcg

CALCULATION RESULT CARD
After the user presses “Calculate,” show a large, clean result card.

The primary result should say:

“Draw to XX units”

Below it, show:
- Volume: X.XX mL
- Concentration: XXXX mcg/mL, mg/mL, or IU/mL
- Amount per syringe unit: XX mcg, mg, or IU
- Theoretical doses per vial: XX

Use sensible decimal precision:
- Syringe units: up to 1 decimal place
- Volume: up to 3 decimal places
- Concentration: up to 2 decimal places
- Avoid unnecessary trailing zeros

The words “Draw to XX units” should be the most visually prominent information on the screen.

Add a simple visual representation of the selected syringe:
- A horizontal syringe scale
- Mark the calculated plunger position
- Show 0–50 units for the 0.5 mL syringe
- Show 0–100 units for the 1 mL syringe
- Keep this diagram clean and functional, not decorative

VALIDATION AND WARNINGS
Prevent calculation when:
- Required fields are empty
- Any number is zero or negative
- BAC water is zero
- Desired dose exceeds the total amount in the vial
- Units cannot be converted
- Values are not valid numbers

Show a warning when:
- The calculated volume exceeds the selected syringe capacity
- The result is below one syringe unit
- The result requires a fraction of a syringe unit that may be difficult to measure
- The theoretical number of doses is less than one

Warnings should not prevent the user from seeing the calculation unless the calculation is mathematically invalid.

Example warning:
“This amount may be difficult to measure accurately using the selected syringe.”

Do not tell the user whether a dose is medically safe, high, low, normal, or recommended.

- Navigate to the Calendar

- Syringe size

- End date

Deleting a cycle should require confirmation. Prefer archiving rather than permanent deletion when historical records exist.

MEDICAL AND SAFETY LANGUAGE
Display the following disclaimer during onboarding and beneath the calculator:

“For informational tracking and mathematical calculation only. This app does not provide medical advice, recommend dosages, diagnose conditions, or replace a licensed healthcare professional. Always verify calculations, syringe type, concentration, and product labeling before use.”

Add a checkbox the first time a user saves a cycle:
“I understand that this app does not determine whether a dose is medically appropriate.”

Do not require this checkbox repeatedly.

The app must never:
- Recommend a starting dose
- Suggest increasing or decreasing a dose
- Describe a dose as safe
- Diagnose a reaction
- Recommend purchasing a peptide
- Link to peptide vendors
- Make claims about product purity
- Claim to be HIPAA compliant without a separate legal and technical review

MVP ACCEPTANCE CRITERIA

The app is complete when:

1. A user can calculate a syringe amount from vial strength, BAC water, and desired dose.
2. The result clearly shows both mL and U-100 syringe units.
3. The user can start a cycle directly from the calculation.
4. The user can choose cycle duration, injection frequency, days, and times.
5. Saved injections appear correctly in weekly and monthly calendar views.
6. The calendar displays the correct current cycle week.
7. The user can mark an injection completed or skipped.
8. The user can edit a cycle and apply changes from a selected date forward.
9. Historical completed events retain their original planned and actual values.
10. Dose changes automatically appear in the Journal.
11. Users can manually create, edit, search, filter, and delete journal entries.
12. User data persists after logout and works across devices.
13. Users cannot access another user’s information.
14. The interface works cleanly on modern mobile and desktop browsers.
15. There are no nonfunctional buttons or placeholder pages.

OUT OF SCOPE FOR THE MVP
Do not build:
- AI dose recommendations
- Medical diagnosis
- Telemedicine features
- Peptide purchasing
- Vendor listings
- Social features
- Public profiles
- Community forums
- Payment processing
- Wearable integrations
- Complicated analytics
- Marketing landing pages
- Achievement badges or gamification
- Native iOS or Android applications

Build the responsive PWA first, with an architecture that can later support a native mobile application.
